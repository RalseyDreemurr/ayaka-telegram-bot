# Эксплуатация Ayaka 2.0

Начальная настройка, создание чистой базы и проверка Telegram описаны в
[README](README.md#быстрая-установка). Команды ниже рассчитаны на Linux
и venv в каталоге проекта.

## Ручной запуск

```bash
cd ~/ayaka-telegram-bot
./venv/bin/python -B main.py --release
```

Ручной запуск работает без Fish и пользовательского systemd. Для остановки
нажмите `Ctrl+C` в том же терминале. Для перезапуска дождитесь завершения
и запустите ту же команду. Из другого терминала выполните:

```bash
./venv/bin/python -B ayakactl.py status
```

Статус показывает обнаруженный ручной процесс, выбранную SQLite и наличие
модели по адресу Ollama. В ручном режиме эта команда не опрашивает Telegram.

## Управление через Fish и журналы

```fish
cd ~/ayaka-telegram-bot
./start_ayaka.fish --release
./status_ayaka.fish
./restart_ayaka.fish --release
./stop_ayaka.fish
```

Fish вызывает контроллер через `venv/bin/python`. Если unit-файлы не
установлены, контроллер создаёт временные службы. Второй вызов старта
проверяет уже действующую службу. Ручной экземпляр останавливают в исходном
терминале. Команда `systemctl --user stop ayaka.service` останавливает
только Аяку.

Прямой режим запускает только бота. При локальном SOCKS5 контроллер
может использовать уже работающий Tor или запустить служебный. `stop_ayaka.fish`
останавливает Tor только в службе `ayaka-tor.service`. Постоянные и
временные службы читают тот же `.env` из каталога проекта. Запишите туда
параметры, которые нужны службе. Переменные только из вызывающего Fish
автоматически в окружение systemd не передаются.

Служба сообщает готовность после `getMe` и подготовки polling. В режиме
SOCKS5 ему предшествует проверка SOCKS5 CONNECT. Первый успешный `getUpdates` следует после этого сигнала.
Polling может работать при недоступной Ollama. После обработки обновления
позиция опроса сохраняется в SQLite. Обычные личные и групповые ответы,
ответы из дневника, ответы на команды и уведомление о добавлении бота в
группу используют один порядок отправки. Перед запросом к Telegram Аяка
фиксирует попытку. При явном отказе с `retry_after` она сохраняет срок
повтора. Служебный файл в закрытом подкаталоге `.ayaka-delivery` рядом с
базой позволяет восстановить отказ после перезапуска, если запись в SQLite
не удалась. Храните каталог рядом с рабочей базой.

Для защиты от повторной доставки Аяка хранит минимум служебных данных до
двух суток: ID чата и сообщения, дату и состояние отправки. Это относится
и к ответам на команды в группах с отключённым архивом. Тексты дневника,
ответов команд и сообщений из таких групп в журнал доставки не попадают.
На безопасном повторе дневник читается заново, поэтому удалённые записи не
возвращаются в ответ. Если при перезапуске потерян контекст уточнения
группы, Аяка просит полный вопрос вместо угадывания контекста. Уже
подготовленный ответ Ollama можно повторно использовать в том же процессе
в течение двух минут, если разрешённый контекст совпадает. После
перезапуска он строится заново только при разрешённом повторе.

Статус «печатает» служит подсказкой и не хранится. Периодические задачи
архива обновляют SQLite и не публикуют сообщения сами. Инициативные ответы
запускаются только входящими сообщениями и проверяются так же, как
остальные групповые ответы.

При явном отказе без возможности повтора, например при запрете отправки
в чат, попытка закрывается без отметки об успешной доставке. Если Telegram
мог принять сообщение, а подтверждение потерялось, Аяка
не повторяет отправку автоматически. Ответ может не дойти или остаться
без записи в истории. Подтверждённый отказ тоже может потеряться, если
процесс прервался до его фиксации или оба способа сохранения отказа были
недоступны. Для ответов из дневника и команд, отправленных до обновления,
записей о доставке ещё нет.

```fish
systemctl --user show ayaka.service ayaka-tor.service -p LoadState,ActiveState,SubState,Result
tail -n 50 ~/.local/state/ayaka/bot.log
tail -n 30 ~/.local/state/ayaka/tor.log
```

Если установлен `XDG_STATE_HOME`, журналы находятся в его подкаталоге
`ayaka`. Они ротируются. Подробный вывод управляемого Tor заглушён,
поскольку может содержать параметры мостов. Временные ошибки Telegram
и SQLite имеют ограниченные повторы. systemd даёт до 210 секунд на
штатную остановку.

## Необязательный Tor

Прямой режим в шаблоне не использует Tor. Для SOCKS5 в `.env`:

```dotenv
TELEGRAM_TRANSPORT=socks5
TELEGRAM_PROXY_URL=socks5://127.0.0.1:9050
```

Задайте URL работающего прокси. Для собственного Tor используйте безопасную
копию [torrc.example](systemd/torrc.example), если локального torrc ещё нет:

```bash
mkdir -p -m 700 ~/.config/tor-ayaka ~/.local/share/tor-ayaka
test -e ~/.config/tor-ayaka/torrc || install -m 600 systemd/torrc.example ~/.config/tor-ayaka/torrc
```

В torrc укажите фактический абсолютный `DataDirectory` и оставьте локальный
`SocksPort`. При использовании мостов задайте `UseBridges 1`,
`ClientTransportPlugin` с фактическим путём к obfs4 и храните строки `Bridge`
только в закрытом файле. Для другого пути к torrc задайте `AYAKA_TORRC`.
[Получение мостов Tor](https://support.torproject.org/tor-browser/circumvention/getting-bridges/)

Для ручного запуска Tor используйте отдельный терминал:

```bash
tor -f "$HOME/.config/tor-ayaka/torrc"
```

Убедитесь, что Tor закончил загрузку и адрес совпал. Не заполняйте токен в
команде проверки маршрута:

```bash
curl --socks5-hostname 127.0.0.1:9050 --max-time 20 -I https://api.telegram.org
```

Если указан удалённый SOCKS5, Аяка использует его без запуска местного Tor.
При отказе SOCKS5 Аяка сохраняет заданный маршрут.

## Постоянные пользовательские службы

Шаблоны рассчитаны на клон в `~/ayaka-telegram-bot`. Для другого каталога
укажите фактические пути в `WorkingDirectory`, `ExecStart` и
`ExecCondition` в копиях файлов. Если службы с такими именами уже установлены, сначала проверьте,
кому они принадлежат, и согласуйте замену. Имена рассчитаны на один
экземпляр на Linux-пользователя.

```fish
cd ~/ayaka-telegram-bot
mkdir -p ~/.config/systemd/user
install -m 644 systemd/ayaka.service ~/.config/systemd/user/
install -m 644 systemd/ayaka-tor.service ~/.config/systemd/user/
systemctl --user daemon-reload
./start_ayaka.fish --release
```

В прямом режиме `ExecCondition` пропускает пользовательскую службу Tor.
Установленный и запущенный отдельно системный Tor управляется своим unit.
Без `enable` постоянная служба ждёт ручного запуска. systemd внутри WSL
сам по себе не запускает дистрибутив после входа в Windows и не удерживает
его активным. `./start_ayaka.fish --release --wait` сохраняет вызывающий
сеанс, пока служба активна. Автозапуск Windows настраивается отдельно.
[Ограничения systemd в WSL](https://learn.microsoft.com/en-us/windows/wsl/systemd/)

## Резервное копирование и восстановление

```fish
cd ~/ayaka-telegram-bot
mkdir -p -m 700 ~/ayaka-backups
./venv/bin/python -B ayakactl.py backup ~/ayaka-backups/ayaka-snapshot.sqlite3
./venv/bin/python -B ayakactl.py verify-backup ~/ayaka-backups/ayaka-snapshot.sqlite3
```

Резервная копия создаётся через SQLite Backup API с учётом завершённых
транзакций в WAL. Файл назначения должен отсутствовать. Снимок проходит
проверку целостности и внешних ключей и может содержать частные данные.

Для восстановления остановите бота, сделайте снимок текущей базы,
проверьте выбранную резервную копию и укажите её отдельный экземпляр в
`DB_PATH`. Используйте снимок той же версии схемы. Более старая копия
может вернуть удалённые записи, личные отказы и прежнюю позицию polling.
Проверьте настройки приватности до запуска.
