# Ayaka 2.0

## О проекте

Аяка — русскоязычный Telegram-бот для личных разговоров и групп. Она любит
игры, аниме, Linux и компьютеры, пишет в женском роде и обходится без эмодзи.
Ответы генерирует модель в Ollama. Приложение на Python обрабатывает обновления
через Telegram Bot API и хранит разрешённую историю в SQLite.

## Возможности Аяки

- В личке отвечает владельцу, которого проверяет по числовому Telegram ID.
- В группах с разрешённым сбором отвечает на имя «Аяка», `@username` и
  ответы на сообщения бота. Инициативные реплики ограничены активностью
  чата и паузой между ответами.
- `/callme имя` задаёт обращение в группе, `/callme reset` сбрасывает
  его. Имя не даёт прав владельца. Личность задаётся в [app/persona.py](app/persona.py).
- Хранит закреплённые факты, сводки и двухуровневый дневник. Каждый групповой
  дневник относится к одному чату, общий объединяет разрешённые записи.
- Изолирует историю по чатам, ограничивает параллельные запросы к Ollama,
  учитывает индивидуальный отказ от записи и защищается от повторного запуска.

## Требования к оборудованию

Аяке нужен Python 3.11–3.14 на Linux и доступ к Ollama. Генерацию выполняет
машина, на которой работает Ollama. Её требования зависят от модели, контекста
и драйвера. Для `qwen3:8b-q4_K_M` ориентиром служат 16 ГБ ОЗУ, около 8 ГБ
VRAM для загрузки модели на совместимый GPU и 8 ГБ свободного диска на модели
и окружение. Размер самого тега — около 5,2 ГБ. При запуске на CPU или с
маленькой видеопамятью попробуйте меньшую модель. [Карточка модели](https://ollama.com/library/qwen3:8b-q4_K_M)

## Быстрая установка

Сначала установите системные пакеты по руководству своей платформы и запустите
Ollama. Команды в блоках `bash` выполняются в Bash или совместимой оболочке.

```bash
git clone https://github.com/RalseyDreemurr/ayaka-telegram-bot.git ~/ayaka-telegram-bot
cd ~/ayaka-telegram-bot
python3 -m venv venv
./venv/bin/python -m pip install -r requirements.txt
./venv/bin/python -m pip check
test -e .env || install -m 600 .env.example .env
```

Заполните `.env`, затем создайте чистую SQLite и запустите приложение.

```bash
./venv/bin/python -B ayakactl.py init-db
./venv/bin/python -B main.py --release
```

Пока репозиторий приватный, для клонирования нужен доступ к нему.

## Windows + WSL2 + Ollama

Python, SQLite и Аяка работают в WSL, а Ollama и драйвер GPU — в Windows.
Маршрут к Ollama зависит от сетевого режима WSL. Подробные шаги, включая
NAT, mirrored networking и ограничение порта, приведены в
[руководстве WSL2](docs/install-wsl.md).

## Нативный Arch Linux

Используйте Python из pacman и отдельный venv. Ollama можно запустить на
той же машине или указать достижимый адрес другого сервера. [Руководство Arch Linux](docs/install-arch.md)

## Нативный Ubuntu / Debian

В Ubuntu 24.04 LTS стандартный Python — 3.12, в Debian 13 — 3.13.
В обоих случаях создаётся venv через пакет `python3-venv`.
[Команды установки и проверки](docs/install-ubuntu-debian.md)

## AMD Radeon: ускорение Ollama через Vulkan

ROCm использует вычислительный стек AMD и имеет список поддерживаемых
устройств для каждой ОС. Vulkan — другой GPU-backend. Он полезен, если
ваша карта или драйвер не подходят для ROCm, но драйвер Vulkan видит
физическую Radeon. Наличие Radeon или вывод устройства в `vulkaninfo`
сами по себе не гарантируют загрузку модели на GPU.

В текущих сборках Ollama Vulkan включается автоматически, если backend
установлен. В выпусках с экспериментальным opt-in, например в `0.12.11`,
мог требоваться `OLLAMA_VULKAN=1`. Задавайте переменные на **сервере Ollama**.
`GGML_VK_VISIBLE_DEVICES` принимает индексы из журнала Ollama, например
`1` для `Vulkan1`. После загрузки модели проверьте тип backend по журналу
и загрузку модели через `ollama ps`. [Документация Ollama о GPU](https://docs.ollama.com/gpu) ·
[История настройки Vulkan](https://github.com/ollama/ollama/releases/tag/v0.12.11)

[Драйверы Arch, Ubuntu/Debian и Windows, диагностика и переход на CPU](docs/amd-vulkan.md).

## Настройка Telegram

У [@BotFather](https://t.me/BotFather) создайте бота командой `/newbot`.
Сохраните токен в локальном `.env`. `OWNER_ID` — положительный числовой
ID вашего аккаунта. Его можно взять из ранее проверенных сведений или
собственного [экспорта аккаунта Telegram Desktop](https://telegram.org/blog/export-and-more).

Для обсуждений в группах бот должен видеть обычные сообщения. После
согласования с администраторами проверьте Privacy Mode через `/setprivacy`.
Telegram может потребовать заново добавить бота в уже существующую группу.
Разрешение архивировать данные в самой Аяке настраивается отдельно.
[Privacy Mode в Telegram](https://core.telegram.org/bots/features#privacy-mode)

## Настройка Ollama и выбор модели

На машине с Ollama загрузите тег и проверьте список моделей:

```bash
ollama pull qwen3:8b-q4_K_M
ollama list
```

С хоста бота проверьте доступ к `/api/tags`. Пример для общей Linux-машины:

```bash
curl --noproxy '*' --fail --max-time 10 http://127.0.0.1:11434/api/tags
```

Если Ollama запущена на другой машине, подставьте проверенный URL.
`OLLAMA_MODEL` должен совпадать с тегом из `ollama list`. Контекст
регулируется параметром `OLLAMA_NUM_CTX`. Избегайте вывода HTTP API
в публичную сеть. Для внешнего сервера используйте защищённую доверенную
сеть или HTTPS с обычной проверкой сертификата. Для локальной генерации
используйте загруженную модель. Облачные функции Ollama можно отключить
на её сервере через `OLLAMA_NO_CLOUD=1`. [Ollama на Linux](https://docs.ollama.com/linux) ·
[Настройки Ollama](https://docs.ollama.com/faq)

## Настройка .env

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN`, `OWNER_ID` | Доступ к API и числовой ID владельца. |
| `TELEGRAM_TRANSPORT` | `direct` или `socks5`. Новый шаблон явно выбирает `direct`. Старые настройки с SOCKS5 сохраняют режим. |
| `TELEGRAM_PROXY_URL` | Для `direct` пустая строка. Для `socks5` — URL вида `socks5://127.0.0.1:9050`. |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | Адрес Ollama и тег модели. Базовый пример — `http://127.0.0.1:11434`. |
| `DB_PATH` | Путь к отдельной SQLite. По умолчанию `data/ayaka-release.sqlite3`. Относительный путь отсчитывается от каталога проекта. |
| `GROUP_RAW_DAYS`, `PRIVATE_RAW_DAYS`, `SUMMARY_DAYS` | Сроки хранения разрешённых данных. |
| `GROUP_INITIATIVE_JSON` | Переопределения инициативы для отдельных групп. Это поле не включает архив группы. |

Остальные поддерживаемые параметры перечислены в [шаблоне](.env.example).
Служба читает `.env` из каталога проекта. Переменные вызывающего терминала
и менеджера systemd могут различаться. Задавайте рабочие параметры в файле
с правами `0600`.

## Инициализация SQLite

```bash
./venv/bin/python -B ayakactl.py init-db
./venv/bin/python -B ayakactl.py verify-backup data/ayaka-release.sqlite3
```

Для нестандартного `DB_PATH` проверьте соответствующий файл. `init-db`
создаёт схему с нуля, проверяет её целостность и отказывается заменять
существующий файл. При переносе старого бота учитывайте ожидающие обновления
Telegram. Чистая SQLite не знает прежнего положения polling. [Telegram Bot API](https://core.telegram.org/bots/api#getting-updates)

## Настройка Tor (необязательно)

Если Telegram напрямую доступен, оставьте `direct` из шаблона. Для Tor
укажите `TELEGRAM_TRANSPORT=socks5` и `TELEGRAM_PROXY_URL`. Аяка проверяет
готовность соединения через SOCKS5 до Bot API. TLS проверяется в обоих
режимах. При отказе прокси приложение не переключается на прямой маршрут.
[Пример torrc и запуск](OPERATIONS.md#необязательный-tor)

## Запуск, остановка и перезапуск

| Режим | Запуск | Остановка и состояние |
| --- | --- | --- |
| Вручную | `./venv/bin/python -B main.py --release` | `Ctrl+C` в том же терминале. Для состояния — `./venv/bin/python -B ayakactl.py status`. Для перезапуска дождитесь остановки и запустите снова. |
| Fish и пользовательский systemd | `./start_ayaka.fish --release` | `./stop_ayaka.fish`, `./restart_ayaka.fish --release`, `./status_ayaka.fish`. |

В ручном режиме Fish и systemd не нужны. Для бота с Tor вручную заранее
запустите собственный SOCKS5. В личке владельца проверьте `/help`, `/model`
и обычное сообщение.

## Память, дневники и приватность

По умолчанию сбор групповой истории выключен. Покажите участникам `/privacy`
и согласуйте хранение. После этого владелец включает конкретную группу
из лички командой `/historyon ID согласовано`. `/historyoff ID` отключает
сбор и удаляет историю и связанные записи. `/forgetme` удаляет записи
участника текущей группы и блокирует дальнейшее сохранение, `/optin`
снимает личный отказ.

Сохраняются разрешённый текст и подписи, ID чатов и авторов, имена и ответы.
Медиафайлы не скачиваются. По умолчанию тексты групп хранятся до 14 дней,
ЛС владельца — до 30, сводки и дневники — до 180. Квоты могут сократить
фактический срок. Закреплённые факты удаляются вручную. SQLite не
шифруется. Снимки могут сохранять данные, удалённые позднее из рабочей БД.

## Устранение неполадок

| Симптом | Что проверить |
| --- | --- |
| Telegram не отвечает, HTTP 502 | Фазу запуска и HTTP-статус в `bot.log`. При SOCKS5 сверить адрес, порт и готовность Tor. Ответ корневого домена не подтверждает работу Bot API для токена. |
| Ollama недоступна или модель отсутствует | Проверить `/api/tags` с машины бота, `OLLAMA_BASE_URL` и точный тег из `ollama list`. |
| Ошибка SQLite | Проверить `DB_PATH`, права файла и каталога. Для новой базы использовать `init-db`, для существующей — проверенный снимок. |
| Бот молчит | В личке сверить `OWNER_ID`, в группе — Privacy Mode, согласие и обращение. |
| Уже работает экземпляр | Проверить статус и остановить предыдущий экземпляр. Один токен не должен опрашиваться в нескольких процессах. |

Технические журналы хранятся в `~/.local/state/ayaka`. Перед отправкой
диагностики исключите токен, переписку и адреса мостов. Автотесты
выполняются локально с отдельными SQLite и заглушками:

```bash
./venv/bin/python -B -m unittest discover -s tests
```
